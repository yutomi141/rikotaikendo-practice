# 剣道部サイトでまなぶWeb開発 — 全巻構成

最終ゴール：理工体剣道部の公式サイト `rikotaikendo-web` を保守・運用できるようになること。あわせて、字幕アプリ `kendo-subtitle-app` も保守できるようになること。

進め方：この練習リポジトリで、部のサイトの縮小版を自分の手で作り直す。そのあと本番のリポジトリに小さなPRを出し、保守に入る。

| 巻 | タイトル | フェーズ | 状態 |
|---|---|---|---|
| 第1巻 | 準備と、はじめてのWebページ | 環境構築・①・①' | 完成 |
| 第2巻 | Next.js でつくり直す | ② | 未着手 |
| 第3巻 | データベース・SQL と公開 | ③ | 未着手 |
| 第4巻 | ログインと管理画面 | ④・横展開 | 未着手 |
| 第5巻 | 障害対応と本番サイトの保守 | 障害演習・本番 | 未着手 |
| 第6巻 | 字幕アプリの保守 | 字幕アプリ | 未着手 |

## 第1巻　準備と、はじめてのWebページ

0. この教材の歩き方（ゴール、全体地図、スプシの使い方、質問の型、PRの完了条件）
1. Webの世界地図（ブラウザ・サーバー・DB、部のサイトと字幕アプリの構成図、字幕アプリの裏側を一緒にたどる）
2. アカウントをそろえる（GitHub、Claude の確認）
3. Windows の開発環境をつくる（PowerShell と Git Bash、Git for Windows、初期設定、SSH 鍵、Node.js、VS Code、Claude Code）
4. ターミナルに慣れる（パス、基本コマンド、ハンズオン）
5. Git と GitHub の基本（add/commit/push、差分を読む、取り消し、よくあるエラー）
6. Claude Code と組む（権限の確認、CLAUDE.md、頼み方の5原則、育てるサイクル、使用量の節約、3つの掟）
7. フェーズ① HTML/CSS で部のトップページをつくる（骨格、CSS、レスポンシブ、開発者ツール、GitHub Pages で公開）
8. フェーズ①' JavaScript で動きをつける（変数・配列・オブジェクト・関数、DOMとイベント、FAQ の開閉、部員の絞り込み）
- 付録：コマンド早見表、エラー逆引き、用語集

## 第2巻　Next.js でつくり直す（フェーズ②）

1. npm と package.json（依存関係、lockfile、`npm run dev/build`）
2. TypeScript 入門（型、型エラーの読み方）
3. React 入門（コンポーネント、props、state、配列から一覧をつくる、key）
4. Next.js App Router（ファイルがそのまま URL になる、layout、Server Component と Client Component）
5. Tailwind CSS（ユーティリティクラス、レスポンシブ）
6. 既存コードの読み方（本番 `rikotaikendo-web` の FAQ ページを読む）
7. 練習リポジトリでのチーム開発（Collaborator、ブランチ、PRテンプレート、レビュー対応、コンフリクト）
8. FAQ ページをつくる → 腕だめし

## 第3巻　データベース・SQL と公開（フェーズ③）

1. データベースとは（表・行・列、主キー、型、制約、公開フラグ。部員・大会結果・FAQ の表で考える）
2. SQL でデータを読む（SELECT、WHERE、ORDER BY、LIMIT、LIKE、NULL の扱い）
3. SQL でまとめる・つなぐ（COUNT・GROUP BY による集計、JOIN による表の結合。例：「期ごとの部員数」「大会ごとの結果一覧」）
4. SQL でデータを変える（INSERT、UPDATE、DELETE。WHERE を忘れると全件が変わる事故、トランザクション）
5. テーブル設計（正規化の入口、外部キー、インデックス、本番のテーブル定義を読む）
6. Supabase のクエリと SQL の対応（`.select().eq().order()` が裏でどんな SQL になるか）
   - 演習は Supabase の SQL Editor で、ダミーの部員データに対して行う。各節に「この結果を出す SQL を書け」の問題を付ける
7. Supabase（プロジェクトを作る、テーブルと seed を SQL で Git 管理する、空の DB から再現する）
8. RLS（Row Level Security）で読み取りを制御する
9. 環境変数と秘密情報（`.env.local`、公開してよいキーと秘密のキー）
10. Server Component から Supabase のデータを読む
11. Vercel に公開する（Preview デプロイ、環境変数、ログ）
12. キャッシュと ISR（「更新したのに表示が古い」の仕組み）
13. 腕だめし（非公開のデータが表示されてしまうバグを直す）

## 第4巻　ログインと管理画面（フェーズ④・横展開）

1. 認証の仕組み（OAuth、セッション、Cookie）
2. 認証の雛形を読む（三角が用意したもの）
3. 管理者の判定（`admin_profiles`）と、書き込み用の RLS
4. フォームと入力検証（zod）
5. FAQ の CRUD（Server Actions）
6. 拒否されることを確かめる（未ログインの人・管理者でない人は書き込めない）
7. 横展開（トップ、部員紹介、大会結果）
8. 腕だめし

## 第5巻　障害対応と本番サイトの保守

1. 障害演習（ビルドの失敗、環境変数の入れ忘れ、DB に接続できない、表示が古いまま）
2. ログの読み方（Vercel、ブラウザの開発者ツールの Network タブ、Supabase）
3. 本番リポジトリを読む（i18n、Tiptap、dnd-kit は「読めればいい」）
4. 本番への小さな PR（favicon、OGP 画像、誤字）
5. 運用（ニュースの更新、年度ごとの名簿の更新、管理者の交代、依存パッケージの更新）

## 第6巻　字幕アプリの保守

1. 全体の構成（Next.js / Supabase / GitHub Actions / FFmpeg / YouTube API / Vercel）
2. 処理の流れをたどる（受付 → 保存 → Actions → FFmpeg → 完了通知 → DB の状態更新）
3. 失敗したときに集める情報
4. 再実行してよいかどうかの判断と、重複アップロードの避け方
5. 小さな修正の PR

## 必須の到達点（スプシ上部の5項目）

1. 本番のリポジトリをローカルで起動できる
2. 小さな修正を自分で確かめてから PR を出せる
3. 壊れている箇所を絞り込んでから相談できる
4. 管理画面の運用と、年度ごとの名簿の更新ができる
5. 字幕アプリで失敗した処理を、再実行してよいか判断できる

## ビルド方法

```bash
cd docs/textbook/vol1 && latexmk vol1.tex
```

LuaLaTeX（TeX Live 2025 以降）と `jlreq`・`piton`・`tcolorbox` が必要。フォントはヒラギノを使う（macOS 向け）。
