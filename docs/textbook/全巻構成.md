# 剣道部サイトでまなぶWeb開発 — 全巻構成

最終ゴールは2つ。理工体剣道部の公式サイトを保守・運用できるようになることと、字幕アプリ `kendo-subtitle-app` を保守できるようになること。

進め方：
1. 練習リポジトリで、部のサイトの縮小版を自分の手で作る（素の JavaScript + Cloudflare Workers + D1。フレームワークは使わない）
2. 本番のサイトは、三角の CMS テンプレート（同じ Cloudflare の土台）を三角と一緒に当てて作る
3. 自分で作ったものとテンプレートを比べて読み、保守に入る

セキュリティは、IPA「安全なウェブサイトの作り方」（改訂第7版）とそのチェックリストを手元に置き、該当する章を示す。全部を自力で満たすことは目標にせず、「意識する」「AI にチェックリストと照らし合わせてもらう」ところまでを求める。

## 第1巻　準備と、はじめての Web ページ

0. この教材の歩き方
1. Web の世界地図
2. アカウントをそろえる（GitHub、Claude）
3. Windows の開発環境をつくる
4. ターミナルに慣れる
5. Git と GitHub の基本
6. Claude Code と組む
7. フェーズ① HTML/CSS で部のトップページをつくる（練習問題16問）
8. フェーズ①' JavaScript で動きをつける（練習問題12問）
- 付録：コマンド早見表、エラー逆引き、用語集、練習問題の解答例

## 第2巻　データをサーバーに置く — Cloudflare Workers（フェーズ②）

1. 第1巻の `data.js` の限界（データを変えるにはコードを直すしかない → サーバーに置く理由）
2. モダンな JavaScript の追加分（`import`/`export`、分割代入、スプレッド、`?.`、`async`/`await` と Promise）
3. Cloudflare のアカウントと wrangler（手元で動かす `wrangler dev`）
4. Worker の基本（リクエストを受けてレスポンスを返す、URL で処理を振り分ける）
5. 第1巻のページを Worker から配信する（静的ファイル）
6. API をつくる（`GET /api/faqs` が JSON を返す）
7. ページから `fetch` で API を読む
8. 練習リポジトリでのチーム開発（ブランチ、PR テンプレート、レビュー対応、コンフリクト）
9. `workers.dev` に公開する
10. 腕だめし・説明タスク

## 第3巻　データベースと SQL — D1（フェーズ③）

1. データベースとは（表・行・列、主キー、型、制約、公開フラグ）
2. SQL で読む（SELECT、WHERE、ORDER BY、LIMIT、LIKE、NULL）
3. SQL でまとめる・つなぐ（COUNT・GROUP BY、JOIN。例：期ごとの部員数）
4. SQL で変える（INSERT、UPDATE、DELETE。WHERE を忘れると全件が変わる事故）
5. テーブル設計（お知らせ・大会結果・部員・FAQ の表を作る。外部キー、インデックス）
6. D1 を使う（`schema.sql` と seed を Git 管理する、手元と公開先の DB の違い）
7. Worker から D1 を読む（プレースホルダ ＝ SQL インジェクション対策。IPA 1.1）
8. 公開ページを DB から作る（お知らせの一覧と詳細、大会結果、部員紹介）
9. XSS とエスケープ（IPA 1.5）
10. 腕だめし（非公開のお知らせが表示されてしまうバグを直す）
- 各節に「この結果を出す SQL を書け」の練習問題を付ける

## 第4巻　ログインと管理画面（フェーズ④）

1. 認証と認可の違い
2. パスワードの保存（ハッシュ化。Web Crypto の PBKDF2）
3. セッションと Cookie（HttpOnly・Secure・SameSite。IPA 1.4）
4. ログインとログアウト（試行回数の制限）
5. 管理者かどうかの判定（アクセス制御。IPA 1.11）
6. CSRF 対策（IPA 1.6）
7. 入力の検証（サーバー側でも確かめる理由）
8. 管理画面：お知らせ・大会結果・部員・FAQ の追加・編集・削除
9. 拒否されることを確かめる（未ログインの人・権限のない操作）
10. 問い合わせフォームの受付（DB に保存するだけ。メールは送らない）
11. セキュリティヘッダ（CSP、クリックジャッキング対策。IPA 1.9）
12. IPA のチェックリストを Claude と一緒に当てる
13. 腕だめし・説明タスク

## 第5巻　障害対応と、本番サイトをつくる（フェーズ⑤）

1. 障害演習（デプロイの失敗、設定（binding）の入れ忘れ、DB の表の作り忘れ、表示が古いまま）
2. ログの読み方（`wrangler tail`、Cloudflare のダッシュボード、開発者ツールの Network）
3. 三角の CMS テンプレートを読む（自分で作ったものと比べる）
4. 本番をつくる：部の共用アカウントにテンプレートを当てる（三角と一緒に）
5. 記事型を足す（大会結果は三角が手本で、部員は柴山が担当）
6. 運用（名簿の年度更新、管理者の交代、バックアップ、依存の更新）

## 第6巻　字幕アプリの保守（フェーズ⑥）

1. 全体の構成（Next.js / Supabase / GitHub Actions / FFmpeg / YouTube API / Vercel）
2. Next.js と TypeScript を「読む」ための最小限（自作の CMS との対応表）
3. 処理の流れをたどる（受付 → 保存 → Actions → FFmpeg → 完了通知 → DB の状態更新）
4. 失敗したときに集める情報
5. 再実行してよいかどうかの判断と、重複アップロードの避け方
6. 小さな修正の PR

## 必須の到達点（スプシ上部の5項目）

1. 本番のリポジトリをローカルで起動できる
2. 小さな修正を自分で確かめてから PR を出せる
3. 壊れている箇所を絞り込んでから相談できる
4. 管理画面の運用と、年度ごとの名簿の更新ができる
5. 字幕アプリで失敗した処理を、再実行してよいか判断できる
